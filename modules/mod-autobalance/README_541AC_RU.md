# AutoBalance для ядра yakanikel-droid/541ac

Эта сборка основана на `azerothcore/mod-autobalance` версии `2.2.0`, commit
`73d4ad3c379fbfc35c63b5b9b44fba1f7d9e213d`, и проверена с ядром
`yakanikel-droid/541ac`, commit `9ec836c4e21ed1a7fc6d589fdba508a87968a978`.

## Что проверено

- CMake обнаруживает модуль как статический модуль AzerothCore.
- Все исходники AutoBalance компилируются с C++20 и API ядра `541ac`.
- Модуль собирается одновременно с уже установленными модулями ядра.
- `AutoBalance.conf.dist` включается в список устанавливаемых конфигураций.
- SQL-миграции модулю не требуются.
- API-хуки существ, карт, игроков, юнитов, объектов и мира совместимы.
- Исправлен тип ключа динамических настроек с `uint8` на `uint32`: без этого
  Map ID выше `255` обрезались и настройки карт `1000-1018` не находились.
- Добавлено сопоставление Map ID `1000-1018` с исходными картами при чтении
  диапазонов уровней из `LFGDungeons.dbc`. Дополнительный клиентский DBC для
  AutoBalance не требуется.
- Добавлен условный CMake-shim для ошибки ядра: пустой каталог скриптов
  `Custom` регистрируется, но функция `AddCustomScripts()` отсутствует. Shim
  создаётся только пока в `Custom` нет файлов `.cpp`.

## Исправление для героических классических карт

В ядре `541ac` героические копии классических подземелий используют отдельные
Map ID `1000-1018`. Штатный AutoBalance содержит специальные настройки для
сложных по геометрии классических инстансов, но знает только исходные Map ID.

В этой сборке специальные настройки продублированы для:

| Оригинал | Героическая копия | Настройка |
|---:|---:|---|
| 229 | 1010 | Пик Чёрной горы: динамический диапазон уровней |
| 230 | 1015 | Глубины Чёрной горы: динамический диапазон уровней |
| 189 | 1018 | Монастырь Алого ордена: расчёт существ в радиусе 500 |

Это предотвращает смешивание уровней между удалёнными частями больших карт.

Для расчёта ожидаемого диапазона уровней все карты `1000-1018` используют
LFG-данные своих исходных карт. Собственный Map ID при этом сохраняется для
конфигурации, сохранений инстанса и диагностических команд.

## Установка

Распакуйте каталог модуля в корень ядра:

```text
/home/kanika/Azerothcore/azerothcore-wotlk/modules/mod-autobalance
```

Итоговый файл должен существовать:

```text
/home/kanika/Azerothcore/azerothcore-wotlk/modules/mod-autobalance/src/AutoBalance.cpp
```

Выполните чистую конфигурацию и сборку обычным способом вашего ядра. Для
статической сборки должны использоваться параметры:

```bash
-DMODULES=static -DSCRIPTS=static
```

После установки конфигурация появится в каталоге конфигураций сервера как
`AutoBalance.conf`. Если файл не был создан автоматически, скопируйте
`conf/AutoBalance.conf.dist` и уберите окончание `.dist`.

## Первый запуск

По умолчанию модуль включён:

```ini
AutoBalance.Enable.Global=1
AutoBalance.MinPlayers=1
AutoBalance.MinPlayers.Heroic=1
AutoBalance.LevelScaling=1
AutoBalance.LevelScaling.Method="dynamic"
```

Для диагностики добавьте в `worldserver.conf` после основного логгера модулей:

```ini
Logger.module.AutoBalance=4,Console Server
Logger.module.AutoBalance_CombatLocking=4,Console Server
Logger.module.AutoBalance_DamageHealingCC=4,Console Server
Logger.module.AutoBalance_StatGeneration=4,Console Server
```

Уровень `4` показывает информационные сообщения. Для подробной диагностики
временно используйте `5`.

## Проверка в игре

1. Войдите в обычное классическое подземелье одним персонажем.
2. Выполните `.ab mapstat`.
3. Возьмите существо в цель и выполните `.ab creaturestat`.
4. Переключите героическую сложность и войдите в копию с Map ID `1000-1018`.
5. Повторите обе команды и сравните уровень, количество игроков и множители.
6. Измените один параметр конфигурации и выполните `.reload config`.

Особенно проверьте карты `1010`, `1015` и `1018`: в выводе должна быть
определена отдельная героическая карта, а расчёт уровня не должен учитывать
существ из удалённых крыльев.

## Важное ограничение текущего проекта

AutoBalance изменяет характеристики только существ, которые реально загружены
на карте. В отчёте `mod-heroic-classic-dungeons` указано, что существа в карты
`1000-1018` пока не скопированы. До появления спавнов на героических копиях
модулю нечего масштабировать. Он не создаёт спавны и не создаёт отдельный лут.

Для нормальных подземелий AutoBalance работает сразу. Для героических копий он
начнёт масштабировать существ после копирования `creature`-спавнов или иной
реализации их загрузки на новые Map ID.

## Удаление

Удалите каталог `modules/mod-autobalance`, очистите каталог сборки и соберите
ядро заново. SQL откатывать не требуется.
