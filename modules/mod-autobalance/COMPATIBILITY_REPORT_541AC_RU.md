# Отчёт о совместимости AutoBalance с 541ac

Дата проверки: 21 августа 2026 года.

## Проверенные версии

- Ядро: `yakanikel-droid/541ac`, commit
  `9ec836c4e21ed1a7fc6d589fdba508a87968a978`.
- База модуля: `azerothcore/mod-autobalance` 2.2.0, commit
  `73d4ad3c379fbfc35c63b5b9b44fba1f7d9e213d`.
- Режим: Linux x86-64, GCC 13.3, C++20, Release,
  `MODULES=static`, `SCRIPTS=static`.

## Результат

Модуль совместим после внесённых адаптаций. Полный `worldserver` собран и
слинкован вместе с `mod-account-shop`, `mod-auto-learn-spells`,
`mod-nova-enhancement` и `mod-world-chat`. Полученный ELF запущен с параметром
`--version`; повторная сборка завершилась без перекомпиляции исходников.

Конфигурация `AutoBalance.conf.dist` присутствует в CMake install script,
установлена в `etc/modules` и побайтно совпадает с исходной. SQL-миграции не
требуются.

## Найденные несовместимости и исправления

| Уровень | Проблема | Последствие | Исправление |
|---|---|---|---|
| Критический | Ключ `levelScalingDynamicLevelOverrides` имел тип `uint8` | Map ID `1000-1018` обрезались до 8 бит; настройки применялись к неверным картам или не находились | Тип ключа и загрузчика изменён на `uint32` |
| Критический | Для карт `1000-1018` нет собственных записей `LFGDungeons.dbc` | AutoBalance получал диапазон уровней `0-0` и исключал существ из масштабирования | Для чтения LFG-диапазона добавлено соответствие каждой героической копии исходной карте; реальный Map ID инстанса не меняется |
| Высокий | Пустой каталог `src/server/scripts/Custom` ядра регистрируется как статический модуль, но `AddCustomScripts()` отсутствует | Ошибка линковки `undefined reference to AddCustomScripts()` | Условный CMake-shim добавляет пустую функцию только при отсутствии `.cpp` в `Custom` |
| Средний | Специальные настройки больших классических карт были заданы только для Map ID `229`, `230`, `189` | Неверный охват существ в удалённых крыльях героических копий | Настройки продублированы для `1010`, `1015`, `1018` |
| Низкий | GCC 11 игнорирует `[[maybe_unused]]` у двух неиспользуемых полей отладки | Два предупреждения `-Wattributes` | Неиспользуемые поля удалены; одноимённые локальные переменные сохранены |

## Проверка API и соседних модулей

Все используемые AutoBalance хуки найдены как в декларациях ScriptMgr ядра,
так и в местах вызова: конфигурация, вход/выход с карты, добавление/удаление и
обновление существ, выбор уровня, урон, лечение, ауры, GameObject, состояния
encounter и события игрока. Изменений сигнатур для этой версии ядра не
потребовалось.

В установленных модулях ядра не найдено другого обработчика, который меняет
уровень или базовые характеристики существ. Если позднее будет установлен
другой модуль масштабирования, его совместную работу с AutoBalance необходимо
проверять отдельно.

## Ограничения и риски запуска

По README проекта героических классических подземелий существа на карты
`1000-1018` ещё не скопированы. AutoBalance не создаёт спавны или лут и начнёт
масштабировать эти карты только после появления на них существ.

В upstream AutoBalance остаётся открытым отчёт о слишком быстром убийстве
Immol'thar дружественными NPC в Dire Maul (issue 224). Это поведенческий риск,
а не ошибка компиляции; без воспроизводимого запуска сервера и базы данных
спекулятивное изменение боевой логики не вносилось. После заполнения карты
`1011` её следует включить в обязательный игровой тест.

## Рекомендуемая приёмка на работающем сервере

1. Проверить обычный инстанс командами `.ab mapstat` и
   `.ab creaturestat` с выбранным существом.
2. Повторить на картах `1010`, `1015`, `1018` после добавления спавнов.
3. Убедиться в логе `module.AutoBalance`, что для новых карт указан LFG-источник.
4. Пройти Dire Maul `429` и его копию `1011`, наблюдая бой с дружественными NPC.
5. Проверить соло и группой, затем выполнить `.reload config` и повторить тест.

Подробная установка и параметры первого запуска приведены в
`README_541AC_RU.md`.
