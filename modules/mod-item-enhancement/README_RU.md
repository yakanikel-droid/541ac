# Улучшение предметов для AzerothCore 3.3.5a

Комплект предназначен для ядра `yakanikel-droid/541ac`. Он содержит серверный модуль, SQL, конфиг и встроенное
клиентское окно FrameXML. Это не аддон: окно загружается самим интерфейсом клиента из MPQ-патча.

## Возможности

- NPC `Кузнец драконьей ковки <Мастер улучшения снаряжения>`.
- Вкладки `Заточка` и `Перенос`.
- Цена заточки зависит от ItemLevel и целевого уровня.
- Отдельные шанс и итоговый процент характеристик для каждого уровня.
- Белый список усиливаемых ItemModType.
- Белый список SpellID: у них масштабируется только BasePoints предметного заклинания.
- Обычная неудача сбрасывает предмет до +0.
- Камень защиты заменяет полный сброс потерей одного уровня.
- Камни шанса на +7% и +10%.
- Три серии гарантированных сфер I–X: ItemLevel до 100, до 200 и без ограничения.
- Запрет наследуемых предметов, чёрный и белый списки ItemEntry.
- Перенос снимает заточку с исходного предмета и ставит её на незаточенный целевой предмет.

## Сервер

1. Скопируйте каталог `mod-item-enhancement` в `azerothcore-wotlk/modules/`.
2. Из корня AzerothCore примените обязательную защиту служебного слота:

   `git apply modules/mod-item-enhancement/patches/required_item_socket_guard.patch`

   Она не даёт ядру ошибочно считать метку заточки дополнительным сокетом.
3. Скопируйте `conf/mod_item_enhancement.conf.dist` в каталог конфигурации сервера либо позвольте установке модуля
   установить dist-файл штатно.
4. Повторно запустите CMake и соберите ядро.
5. SQL из `data/sql/db-world/base/` устанавливается штатным загрузчиком SQL модулей. При ручной установке выполните
   `item_enhancement_world.sql` в world-базе.
6. Добавьте spawn NPC 900000 в таблицу `creature` на выбранных координатах. В SQL оставлен шаблон.

Уровень хранится в `PRISMATIC_ENCHANTMENT_SLOT` как EnchantID `50000 + уровень`. Предмет с уже занятым дополнительным
сокетом модуль не принимает, поэтому существующая кузнечная механика не уничтожается.

## Клиент

1. Извлеките клиентский `Interface/FrameXML/FrameXML.toc` в рабочую папку MPQ.
2. Добавьте в конец `FrameXML.toc` строку:

   `ItemEnhancementFrame.xml`

3. Скопируйте из комплекта оба файла:

   - `client/Interface/FrameXML/ItemEnhancementFrame.xml`
   - `client/Interface/FrameXML/ItemEnhancementFrame.lua`

   в `Interface/FrameXML/` клиентского MPQ-патча.
4. Извлеките оригинальный `DBFilesClient/SpellItemEnchantment.dbc` клиента и выполните:

   `python tools/patch_enchantment_dbc.py SpellItemEnchantment.dbc SpellItemEnchantment_patched.dbc`

5. Положите полученный файл в клиентский MPQ как `DBFilesClient/SpellItemEnchantment.dbc`.
6. Тот же полученный DBC скопируйте на сервер в `Data/dbc/SpellItemEnchantment.dbc`.

Записи 50001–50010 не дают характеристик сами. Они являются видимой меткой `Улучшение +N`; реальные бонусы считает
сервер. Встроенный FrameXML находит эту метку в подсказке и добавляет `+N` к имени предмета. Поэтому заточку видно
владельцу, в ссылках и при осмотре другим игроком, если у него установлен этот клиентский патч.

В окне NPC исходный слот показывает текущий уровень и процент усиления. Слот `Результат` показывает прогноз после
успешной попытки: имя с новым `+N`, целевой процент и обычный тултип предмета. После изменения уровня сервер немедленно
отправляет обновление экземпляра предмета клиенту.

При наведении на предмет в рюкзаке, сумках или собственной экипировке FrameXML запрашивает уровень конкретного
экземпляра у сервера. Поэтому `+N` и пересчитанные разрешённые характеристики отображаются и после закрытия окна NPC.
Клиент не вычисляет уровень самостоятельно и не может назначить предмету заточку через этот запрос.

При стандартном осмотре дружественного игрока его экипировка обрабатывается тем же способом. Сервер разрешает запрос
только для текущей цели в пределах штатной дистанции осмотра и возвращает фактическую заточку выбранного слота.
Клиентский FrameXML должен быть установлен у игрока, который выполняет осмотр.

Подсказки предметов также обрабатываются глобально в `GameTooltip`, `ItemRefTooltip` и сравнительных
`ShoppingTooltip`: уровень виден в окне переноса, ссылках в чате, почте и на аукционе. Для обеих сторон окна обмена
FrameXML дополнительно запрашивает у сервера фактический экземпляр предмета, поскольку штатный пакет обмена WotLK
не передаёт призматическую ячейку. Сервер принимает только номер стороны и ячейки активного обмена, проверяет их
диапазон и сам получает предмет из текущего `TradeData`.

Стандартный Wow.exe 3.3.5a принудительно записывает `0` в четвёртое поле камня при формировании item-link и тем самым
теряет `PRISMATIC_ENCHANTMENT_SLOT`. Это исправляется один раз в центральной функции клиента — отдельных перехватчиков
чата, аукциона, почты или других окон нет. Патчер предназначен только для переданного клиентского файла build 12340 с
SHA-256 `8149c26659957b0d648867ed4795d16d851158c4f6293a2727194abab942b797`:

```bash
python tools/patch_nova_global_enhancement.py Nova.exe Nova-global-item-enhancement.exe
```

Исправленный клиент берёт EnchantID непосредственно из `PRISMATIC_ENCHANTMENT_SLOT`, пропускает только диапазон
50001–50010 через общий item-link formatter, записывает маркер в штатное поле gem4 и добавляет `+N` к тексту ссылки.
Одна и та же ссылка используется сумками, экипировкой, осмотром, чатом, почтой и аукционом. Настоящие чары предмета
не переносятся в другие слоты и не подменяются.

История заточки и история переноса независимы. Переключение вкладки показывает журнал только выбранной операции;
добавление или удаление предмета очищает журнал соответствующей вкладки.

## Перенос

Настройки:

```ini
ItemEnhancement.Transfer.Enable = 1
ItemEnhancement.Transfer.MaterialItemId = 70096
ItemEnhancement.Transfer.MaterialCount = 1
```

Правила:

- исходный и целевой предметы должны быть разными;
- исходный должен иметь заточку;
- целевой должен быть без заточки;
- оба предмета должны проходить общие ограничения;
- после операции исходный становится +0, целевой получает прежний уровень;
- сервер проверяет и списывает настроенное количество ресурса, затем переносит уровень.

## Имена разрешённых характеристик

Полный список значений, которые можно записать в `ItemEnhancement.AllowedStats`:

- основные: `MANA`, `HEALTH`, `STRENGTH`, `AGILITY`, `STAMINA`, `INTELLECT`, `SPIRIT`;
- защита: `DEFENSE_SKILL_RATING`, `DODGE_RATING`, `PARRY_RATING`, `BLOCK_RATING`, `BLOCK_VALUE`;
- меткость: `HIT_MELEE_RATING`, `HIT_RANGED_RATING`, `HIT_SPELL_RATING`, `HIT_RATING`;
- критический удар: `CRIT_MELEE_RATING`, `CRIT_RANGED_RATING`, `CRIT_SPELL_RATING`, `CRIT_RATING`;
- получаемые атаки: `HIT_TAKEN_MELEE_RATING`, `HIT_TAKEN_RANGED_RATING`, `HIT_TAKEN_SPELL_RATING`,
  `HIT_TAKEN_RATING`, `CRIT_TAKEN_MELEE_RATING`, `CRIT_TAKEN_RANGED_RATING`, `CRIT_TAKEN_SPELL_RATING`,
  `CRIT_TAKEN_RATING`;
- скорость: `HASTE_MELEE_RATING`, `HASTE_RANGED_RATING`, `HASTE_SPELL_RATING`, `HASTE_RATING`;
- остальные рейтинги: `RESILIENCE_RATING`, `EXPERTISE_RATING`, `ARMOR_PENETRATION_RATING`;
- сила атаки: `ATTACK_POWER`, `RANGED_ATTACK_POWER`;
- заклинания: `SPELL_POWER`, `SPELL_HEALING_DONE`, `SPELL_DAMAGE_DONE`, `SPELL_PENETRATION`;
- восстановление: `MANA_REGEN`, `HEALTH_REGEN`.

`SPELL_HEALING_DONE` и `SPELL_DAMAGE_DONE` оставлены для совместимости со старыми предметами, но в WotLK считаются
устаревшими. Для обычных предметов следует использовать `SPELL_POWER`.

`ItemEnhancement.ScaleWeaponDamage` управляет базовым уроном оружия отдельно и не является `ItemModType`.

## Важные правила безопасности

- Клиент передаёт только свои номера сумки и ячейки. Сервер преобразует координаты, проверяет принадлежность предмета
  и сохраняет его GUID, а не координаты.
- Перед каждой операцией сервер повторно находит выбранные GUID и проверяет, что предметы всё ещё принадлежат игроку,
  лежат в рюкзаке или надетых сумках, не надеты и не находятся в окне обмена.
- Дистанция до NPC, допустимость предмета, цена, шанс, материал и результат рассчитываются только сервером.
- После выбора нельзя подменить предмет, положив другой в прежнюю ячейку: операция привязана к GUID.
- Особый материал расходуется по одной единице из стопки, а не уничтожает стопку целиком.
- Исходный и целевой предмет переноса запрещено использовать в качестве ресурса переноса.
- Особый материал один и необязательный. Сфера, камень шанса и защита не комбинируются.
- Сфера расходуется только при гарантированном успешном применении.
- Камень шанса расходуется при попытке.
- Защита по умолчанию расходуется только при неудаче.
